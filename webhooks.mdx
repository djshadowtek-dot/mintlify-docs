Webhooks let The Awesome push event notifications to your server in real time — so instead of polling the API for job status, your application is notified the moment an analysis completes or fails. This page covers creating webhooks via the API and verifying incoming payloads.

## Webhook Events

Subscribe to any combination of the following events when registering a webhook:

- **`analysis.completed`** — Fired when an analysis job finishes successfully and results are ready to retrieve.
- **`analysis.failed`** — Fired when an analysis job encounters an unrecoverable error.
- **`data_source.connected`** — Fired when a new data source passes its connection test and is ready to use.
- **`data_source.error`** — Fired when a data source connection check fails or an existing source becomes unreachable.

---

## Register a Webhook

### `POST /webhooks`

Create a new webhook endpoint that The Awesome will call when the specified events occur.

<ParamField body="url" type="string" required>
  The publicly accessible HTTPS URL on your server where The Awesome will send `POST` requests — for example, `https://your-app.com/webhooks/awesome`. The endpoint must return a `2xx` response within 10 seconds.
</ParamField>

<ParamField body="events" type="array of strings" required>
  The list of event types to subscribe to. Accepted values: `analysis.completed`, `analysis.failed`, `data_source.connected`, `data_source.error`. Subscribe to multiple events in a single webhook or create separate webhooks per event type.
</ParamField>

<ParamField body="secret" type="string">
  An optional secret string used to sign every outgoing payload with HMAC-SHA256. Provide this to enable signature verification on your server. See [Verifying Signatures](#verifying-signatures) for implementation details.
</ParamField>

```bash
curl -X POST https://api.the-awesome.ai/v1/webhooks \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://your-app.com/webhooks/awesome",
    "events": ["analysis.completed", "analysis.failed"],
    "secret": "my-webhook-secret"
  }'
```

**Response**

```json
{
  "id": "wh_123abc",
  "url": "https://your-app.com/webhooks/awesome",
  "events": ["analysis.completed", "analysis.failed"],
  "created_at": "2025-01-15T10:00:00Z"
}
```

Store the `id` to manage or delete this webhook later.

## Delete a Webhook

### `DELETE /webhooks/{id}`

Remove a registered webhook. The Awesome will immediately stop sending events to the associated URL.

```bash
curl -X DELETE https://api.the-awesome.ai/v1/webhooks/wh_123abc \
  -H "Authorization: Bearer YOUR_API_KEY"
```

**Response**

A successful deletion returns `204 No Content` with an empty body.

## Webhook Payload

When an event fires, The Awesome sends an HTTP `POST` request to your registered URL with a JSON body in the following shape:

```json
{
  "event": "analysis.completed",
  "timestamp": "2025-01-15T09:01:32Z",
  "data": {
    "analysis_id": "job_xyz789",
    "name": "Q1 Sales Trend",
    "status": "completed",
    "result_ids": ["res_001", "res_002"]
  }
}
```

- **`event`** — The name of the event that fired.
- **`timestamp`** — ISO 8601 timestamp of when the event occurred on The Awesome's side.
- **`data`** — Event-specific payload. For analysis events this includes the job ID, name, final status, and any result IDs produced.

## Verifying Signatures

When you provide a `secret` at registration time, The Awesome signs every outgoing payload with HMAC-SHA256 and includes the signature in the `X-Awesome-Signature` header in the format `sha256=<hex_digest>`. Verify this signature on your server to confirm that the payload came from The Awesome and was not tampered with.

<Warning>
  Always verify webhook signatures in production to prevent spoofed events. An attacker who knows your endpoint URL could otherwise send fabricated payloads to your server.
</Warning>

Here is a Python example that verifies the signature before processing the payload:

```python
import hmac
import hashlib

def verify_signature(payload_body: bytes, secret: str, signature_header: str) -> bool:
    expected = hmac.new(
        secret.encode(),
        payload_body,
        hashlib.sha256
    ).hexdigest()
    return hmac.compare_digest(f"sha256={expected}", signature_header)
```

Call this function early in your webhook handler and reject any request where it returns `False`:

```python
from flask import Flask, request, abort

app = Flask(__name__)
WEBHOOK_SECRET = "my-webhook-secret"

@app.route("/webhooks/awesome", methods=["POST"])
def handle_webhook():
    signature = request.headers.get("X-Awesome-Signature", "")
    if not verify_signature(request.data, WEBHOOK_SECRET, signature):
        abort(403)

    event = request.json
    # Process event...
    return "", 200
```

## Retry Policy

If your endpoint returns a non-`2xx` response or does not respond within 10 seconds, The Awesome treats the delivery as failed and retries automatically with exponential backoff:

| Attempt | Delay after failure |
|---------|---------------------|
| 1st retry | 1 minute |
| 2nd retry | 5 minutes |
| 3rd retry | 30 minutes |

After 3 consecutive failures, The Awesome disables the webhook and sends an email notification to your account's registered address. Re-enable the webhook from **Settings → Webhooks** in your dashboard once you have resolved the issue on your server.

<Tip>
  Make your webhook handler idempotent — check the `event` type and `data.analysis_id` before processing to safely handle any duplicate deliveries that may occur during transient failures.
</Tip>
